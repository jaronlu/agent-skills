# The Last AI Built by Humans: Toward Genuine Recursive Self-Improvement — distilled notes

Source: arXiv:2609.11873; version/date: unknown (id implies 2026-09; abs `vN` not recorded).
Coverage: distilled from accessible text; page-level locations not recorded.

## Problem and contribution
Survey plus position paper on **recursive self-improvement (RSI)**: systems that
turn experience or feedback into *persistent state changes* that improve both
current capability and the process of future improvement. In plain terms, the
system does not just get better — it gets better at getting better. The
contribution is an autonomy-centered framework, not a new model. (Paper claim.)

## Core ideas
1. **HCI — Headroom-Closed Index (Eq. 2)** normalizes any benchmark score to
   0–100: `H = 100 * (s - F0) / (100 - F0)`, where `F0` is the 90th-percentile
   score of the benchmark's **entry year**. `H=0` is that frontier; `H=100` is
   perfect. Cross-source consensus uses weighted averaging (owner tables weight
   highest; self-reported values get a 0.75 discount).
2. **Improvement loop**: experience → propose a modification → evaluate under
   an acceptance rule → retain the accepted change → successor inherits and
   loops. Only an accepted, inherited state change counts as an improvement.
3. **B0–L5 autonomy ladder** (what the AI controls, what humans keep):

   | Level | AI autonomizes | Human retains |
   |---|---|---|
   | B0 | in-task only, no persistence | — |
   | L1 execution | runs a prescribed update | what/how/success |
   | L2 strategy | diagnoses failure and picks the intervention | objective, task boundary, acceptance |
   | L3 experience | decides what practice data to acquire next | — |
   | L4 deployment | distills trajectories, retains/demotes rules from real interaction | external acceptance/governance |
   | L5 meta-improvement | rewrites the improver/evaluator/search policy itself, inherited by successors | mission, safety, protected eval, veto |

   Transitions: B0→L1 persistence; L1→L2 strategy choice; L2→L3 learning
   agenda; L3→L4 deployment feedback; L4→L5 recursive inheritance.

## Evidence and results
Paper's 2026 finding (as stated): bounded, verifiable tasks are near-closed
(grad science ~85.8, math ~86.4), while long interactive tasks lag — software
engineering 52.6, terminal/search agents 56.8, tool agents 39.9. Argument paper:
these numbers support the headroom claim; there is no new model ablation.

The paper also argues that industry already does self-improvement in scattered
forms (self-repairing coding agents, prompt evolution, self-play, AutoML) but
conflates RSI with continual learning / AutoML / agentic AI — hence a common
ruler. (Paper claim.)

## Limitations and open questions
Author-stated: higher autonomy is not a better improvement process. L2+ hazards
include benchmark overfitting via adaptive queries, extra search compute
mistaken for algorithm gains, LLM evaluators sharing the proposer's blind
spots, cherry-picked seeds, and **errors that become heritable**. Distinguish
*structural L5* (self-change persists) from *effective L5* (successors actually
improve).

Inference: novelty is a unifying measurement frame more than a new method;
statistical rigor of the 2026 domain numbers cannot be checked from the paper
alone without the owner tables; a reader cannot reproduce those scores from the
text. Speculation (not in the paper as results): L3 = auto-generate practice
samples from failure clusters; L4 = usage counters that demote dead rules; L5 =
make the `propose_*` function itself the inherited object.

Part A illustrates `hci()` on the paper's domain numbers with synthetic `F0`.
Part B contrasts an L1 (human-prescribed) vs L2 (AI-chosen) loop on a toy
concept, with a held-out no-regression gate as the protected acceptance rule.
Expected: the toy task converges in 2 rounds (HCI 0 → 100) for both L1 and L2 —
a closed loop is necessary but does not by itself prove quality gains. Map
`Policy.rules` to inherited persistent state.
