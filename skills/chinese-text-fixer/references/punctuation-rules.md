# 中文标点与排版规则

本文件是 `chinese-text-fixer` 的规则明细。`SKILL.md` 只保留工作流和分级；解释 finding、处理争议样例、调整脚本时读这里。

## 处理顺序

脚本按以下优先级收集编辑，再按位置应用；重叠时保留位置更早、跨度更长的修复，同位置同跨度才比较下面的优先级：

1. 零宽字符与 BOM
2. 引号方向
3. 全角/半角标点、重复标点、省略号、HTML 实体
4. 标点旁空格
5. 中文与拉丁字母/数字之间的空格

所有规则都跳过受保护区域。`review` 项不产生编辑，只进入报告。

## 受保护区域

默认跳过：

- Markdown frontmatter（文件开头的 `---` 块）。
- Markdown 代码围栏（```` ``` ```` 或 `~~~`）及其内容。
- 行内代码（单反引号或连续反引号包裹）。
- URL（`http://`、`https://`、`ftp://`、`file://` 直到空白或引号）。
- 非 Markdown 文件不启用上述代码保护；需要时用 `--no-skip-code` 反向关闭 Markdown 保护。
- `--text` 与 stdin 按 Markdown 处理，`--no-skip-code` 同样可以关闭这层保护。
- 符号链接、二进制、含 NUL、非 UTF-8 文件不进入规则处理。

受保护的文本仍会出现在 diff 中，只是不会被修改。

## 引号规则

### QT001：方向反转（自动修复）

中文引号用 `“ ”`（U+201C/U+201D）和 `‘ ’`（U+2018/U+2019）。常见错误是结尾也用了开引号：

```text
“数据怎么流转/谁响应手势“   →   “数据怎么流转/谁响应手势”
```

判定方式：用栈记录尚未闭合的开引号。再次遇到同型开引号且中间已有内容时，按闭引号处理。

反转为闭引号还有附加条件：新引号必须紧跟上一段内容，而不是出现在空行之后、行首或冒号（`：`、`:`）之后。这些位置通常是新引用的起点，此时无法判断是“前一个没闭合”还是“后面写反了”，只报告，不翻转。

孤立的闭引号出现在行首、段落首或开括号之后，且后面紧跟中文时，按开引号处理：

```text
”中文   →   “中文
```

### QT002：未闭合或孤立（只报告）

以下情况不自动改，因为补全位置没有唯一答案：

- 全文结束时栈里仍有开引号。
- 闭引号前没有同型开引号，且不在行首/开括号后，例如 `他说”`。
- 同型引号紧邻出现，无法判断是嵌套还是漏写。
- 已有开引号未闭合，后面又在段首、空行后或冒号后出现同型开引号；改哪一端都有风险。

### QT003：嵌套交叉（只报告）

单引号应在双引号内层闭合：

```text
外层“中文‘内层’结束”     正确
外层“中文‘内层”交叉’      交叉，只报告
```

检测到闭引号跨过未闭合的内层引号时，不自动改任何一端。

### 误判保护

- **英寸/尺寸**：`6”`、`6“ ` 这类数字后的引号，如果后面是空白或行尾，按英寸标记跳过。只有栈中没有待闭合开引号时才这样判断；已有开引号时，同一位置的闭引号按配对处理。
- **英文撇号**：`don’t` 中的 `’` 前一个字符是字母，不作为中文闭引号处理。
- **英文引号**：纯英文的 `“hello”` 配对正确时不会被改；方向错误时仍可能被修正，这是脚本的兜底行为。
- **同型嵌套**：中文排版不允许同型引号嵌套；遇到时按“第二次出现即闭合”处理，并在消息中说明。

## 括号与书名号

处理的字符：`（）`、`【】`、`《》`、`〈〉`、`「」`、`『』`。

只报告，不自动修复：

- `BR001`：多余闭括号，或闭括号与最近开括号不匹配。
- `BR002`：括号交叉，例如 `（【）】`。
- `BR003`：开括号未闭合。

不处理 ASCII `()`、`[]`，避免把英文和代码中的括号算成中文错配。

## 全角/半角标点

`FW001` 把中文语境中的半角标点改为全角：

| 半角 | 全角 |
| --- | --- |
| `,` | `，` |
| `.` | `。` |
| `;` | `；` |
| `:` | `：` |
| `?` | `？` |
| `!` | `！` |

触发条件：标点前一个非空格字符是中文。以下不触发：

- 数字、版本号、小数、日期：`1.0`、`2024.10.01`。
- 英文句子结尾：`This is fine.`
- 域名或文件名：`notes.md`、`a.com`。
- 省略号：恰好三个点由 `PU003` 处理；两个点不在任何规则内，既不修改也不报告。

## 重复标点与省略号

- `PU001`：全角重复标点合并，例如 `，，` → `，`、`！！` → `！`。
- `PU002`：中文语境中的重复半角标点，例如 `中文,,` → `中文，`。
- `PU003`：中文后的三个半角点 `...` → `……`（两个 U+2026）。四个及以上点不动，避免把省略号和句点混在一起。

## 空格

`SP001`（standard 自动修复）：

- 中文或闭引号/闭括号与中文标点之间的空格，例如 `中文 ，` → `中文，`、`“话” 。` → `“话”。`。
- 开括号后的空格，例如 `（ 中文` → `（中文`。
- 不跨行处理；只处理空格和制表符。

`SP002`（standard 只报告，strict 自动修复）：

- 中文与拉丁字母/数字直接相邻，例如 `中文Python`、`3个`。
- 建议插入一个空格，但不处理中文与 ASCII 标点之间的情况。
- 该规则可能与出版规范或用户习惯冲突，所以默认只建议。

不处理：

- 行首缩进、Markdown 对齐空格。
- 单个空格是否保留的全局判断；除上述位置外，不重排空格。

## 零宽字符与不可见字符

`ZW001` 删除：

- U+200B 零宽空格。
- U+FEFF BOM 或零宽不换行符（包括文件开头的 BOM）。

`ZW002` 只报告，因为可能有意或影响渲染：

- U+200C 零宽非连接符（波斯文等文字系统有意义）。
- U+200D 零宽连接符（emoji 组合序列有意义）。
- U+2060 词连接符。
- U+00AD 软连字符。
- U+00A0 不间断空格。

不要为了“看起来干净”批量删除 ZWJ/ZWNJ，可能改变 emoji 或文字显示。

## HTML 实体

`EN001` 识别 `&quot;`、`&#8220;`、`&nbsp;` 等实体：

- 默认只报告，提示实际字符。
- `--fix-entities` 或 `strict` profile 下，在非 HTML/XML 文件中解码。
- 解码结果是不可见字符时（`&nbsp;`、`&#8203;` 等）始终只报告：这类字符由 `ZW001`/`ZW002` 管辖，自动解码会把“该不该保留”的判断悄悄做掉。
- `.html`、`.htm`、`.xml` 中始终只报告：在属性值里解码实体可能破坏文档结构。注意三者不在目录扫描的默认后缀里，只有显式传入文件或加 `--ext .html` 才会处理。

## 乱码

`MO001` 只识别、只报告，不自动还原。常见标记：

- U+FFFD 替换字符。
- `锟斤拷`、`烫烫烫`、`屯屯屯`。
- `Ã`、`Â`、`â€`、`ï¼`、`ã€`、`å¤`、`æ–`、`æ‰`、`çš„` 等 UTF-8/GBK 错位后的典型片段。

不自动还原的原因：错编码可能有损，原文无法唯一恢复；应该回到原始文件或数据源确认编码后转码。报告只说明疑似位置和标记，不猜测原文。

## 常见误判与人工复核

- 引号出现在代码、URL、JSON 字符串中：默认受保护或只报告，不自动改。
- `2024“`、`6”`：数字后的引号可能是单位标记，不是引号。
- `中文—English`、破折号、范围号：不在本 skill 的规则范围。
- 中英混排空格：不同出版规范不一致；`SP002` 默认只建议。
- HTML/XML：实体和引号都可能承载结构，始终人工确认。
- 多语言文件：ZWJ/ZWNJ 和引号规则可能属于其他语言，只报告。

复核 `review` 项时，先看该字符在句子中的角色，再决定是否手工修改；不要为了清零报告而批量接受建议。

## 报告与退出码

```text
chinese-text-fixer · profile=standard · dry-run

path/to/file.md:12:8  [QT001 fix] 引号方向：此处应为闭引号 ”
path/to/file.md:20:3  [BR003 review] 开括号 （ 未闭合，未自动补全

--- path/to/file.md
+++ path/to/file.md (fixed)
@@ ...
```

- `fix` 计数包含已进入 diff 的修复；apply 后这些修复已写回。
- `review` 计数是仍需人工判断的项。
- 跳过文件单独列出原因：非 UTF-8、UTF-16、二进制/NUL、符号链接。
- 退出码 `0` 表示无问题或全部 fix 已处理且无 review；`1` 表示仍有发现或复核项；`2` 表示参数、I/O、编码错误，或所有输入都没匹配到文件（此时不输出 `clean`）。
- `--fixed` 只输出修正文本，因此只按剩余 review 计退出码：无 review 为 `0`，有 review 为 `1`。

## 修改脚本时的自检

1. 用 `--text` 覆盖：方向反转、正确配对、未闭合、交叉嵌套、英寸标记、英文撇号、空行或冒号后的新引号、数字紧邻引号。
2. 用临时 Markdown 文件确认：frontmatter、代码围栏、行内代码未被修改。
3. 用 CRLF 文件确认写回后仍为 CRLF。
4. 运行两次 `--apply`，第二次应为 clean，证明幂等。
5. 确认 JSON 的 `line`/`column` 与 diff 对应原文位置。
