## 四、第一小时学习路线：进任何一个仓库先问的 5 个问题

用法：`cd` 进目标仓库，按顺序把下面 5 条提示词逐条粘贴给 codex / claude / repoprompt（提示词原文即正文对应知识点的 P0 提示词）。每条拿到回答后，用前言的「通用追问模板」向深处挖一层，再进下一条。本路线可独立使用；若已按前言「怎么用」步骤 2 粘贴过附录的开场提示词（其中已含整体架构与端到端追踪），可跳过第 1 问直接从第 2 问开始。

**第 1 问 · 先给仓库定性（对应 A8，P0）**——判断它是隐式 while-loop 还是显式图/状态机，决定了接下来该 grep 什么：

```text
我在读这个开源 Agent 仓库的源码，想先判断它的执行模型是隐式 while-loop 还是显式图/状态机。请给出判断与证据：如果存在节点/边/编译/执行引擎一类概念（如 add_node、conditional edge、compile、superstep、checkpoint），请定位图的定义方式、编译产物、以及驱动节点执行的循环，讲清一次调用如何在节点间流转、条件路由在哪里评估、状态与检查点在哪里读写，引用 file:line；如果它只是单个 agent 的 while-loop（step 一直跑到停止条件），也请指出代码证据，并说明每轮 turn 内部是否存在局部的状态机成分（如状态枚举的转换）；两种情况都点出关键数据结构与执行函数名；结尾给出 2-3 个值得继续追问的点。
```

**第 2 问 · 找到心脏（对应 A1，P0）**——定位 agentic loop 本体：

```text
我在读这个开源 Agent 仓库的源码，想搞清楚它的 agentic loop 本体。请定位这个主循环的实现入口——即从用户输入出发、组装 messages、调用模型、解析工具调用、执行工具、把结果回填进对话历史、再判断是否进入下一轮的那段代码，引用 file:line 指出循环体和迭代判断的位置；然后用文字按时间顺序讲清一次完整迭代的数据流：输入如何变成请求、每一轮往 messages 里追加了什么、循环的持续条件是什么；点出承载循环状态的关键数据结构（messages/turn/session 对象等）和核心函数名；若本仓库没有这一机制，请直说并指出最接近的替代实现；引用不到的位置就明说，不要编造；结尾给出 2-3 个值得继续追问的切入点。
```

**第 3 问 · 判断工具协议路线（对应 C2，P0）**——不先判断走哪条路，就找不到工具系统的入口：

```text
我在一个开源 AI Agent 仓库里读源码，只聚焦「工具如何呈现给模型」这一个知识点：请先判断这个仓库用的是原生 tool calling（API 的 tools 参数）还是把工具说明写进 system prompt 的文本协议（再由输出解析器提取调用），然后定位工具清单被组装进请求或 prompt 的实现入口并引用具体 file:line；用文字讲清「工具说明进入上下文 → 模型产出 tool call 文本或结构化字段 → 解析回可执行调用」的完整数据流；点出格式模板/常量与解析函数的名称；若本仓库没有这一机制，请直说并指出最接近的替代实现；引用不到的位置就明说，不要编造；最后给出 2-3 个基于这个仓库实现的追问点。
```

**第 4 问 · 打通调用与回填链路（对应 C4，P0）**——把「模型意图 → 真实执行 → 结果回喂」这条最密集的调用路径走通：

```text
我在一个开源 AI Agent 仓库里读源码，只聚焦「tool call 解析与分发」这一个知识点：从模型响应里的 tool_calls / function_call（或自定义文本协议）到本地 handler 执行、再到 tool result 消息回喂，这条链路是怎么走的？请定位解析入口与执行入口并分别引用具体 file:line；用文字讲清完整调用流程：call_id 如何关联请求与结果、arguments 字符串如何被解析（如果是流式，partial JSON 如何累积）、回填采用什么消息形态（tool role / ToolMessage / 自定义格式）、name 找不到或解析失败时走哪条分支；点出分发函数名与结果消息的构造函数名；若本仓库没有这一机制，请直说并指出最接近的替代实现；引用不到的位置就明说，不要编造；最后给出 2-3 个基于这个仓库实现的追问点。
```

**第 5 问 · 追问行为来源（对应 B1，P0）**——搞清这个 Agent「听谁的」：

```text
我想弄清这个 Agent 仓库的 system prompt 是如何分层组装的：请定位最终发给模型的 system message / instructions 的拼装入口，包括内置 base prompt、项目级指令文件（如 AGENTS.md、CLAUDE.md 或同类机制）的发现与读取（从哪些目录层级发现、发现后是立即读入还是惰性加载、多份文件冲突时谁覆盖谁）、用户自定义规则、以及环境上下文（cwd、git 状态等）的注入层，引用具体 file:line；然后按数据流顺序讲清每一层从哪里读、按什么优先级和顺序拼进最终 prompt、谁会覆盖谁、各层大致占多少篇幅量级；点出这条链路上的关键数据结构与函数名；若本仓库没有这一机制，请直说并指出最接近的替代实现；引用不到的位置就明说，不要编造；最后给出 2-3 个值得继续追问的点。
```

**第一小时之后**：剩下 4 条 P0 补完——A2（循环停止条件）、C1（工具定义 Schema）、D1（会话内短期记忆）、F4（ReAct 循环范式）；首次完整走此路线建议选附录阶段一的 smolagents（见附录第 11 条），之后按附录「建议学习顺序」推进，每换一个仓库重复这 5 问。
